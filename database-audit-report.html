04 · Operational audit

Good pagination; expensive search and fragile transitions.

Performance findings

Job and application lists paginate and scope user-owned relations. However, discovery performs serial upserts; job search runs unindexed substring scans over title, company and description; resume lists load every nested version; analytics executes repeated counts and groups timeline rows in Node. There is no event partitioning, query-specific profile/resume indexes, or vector/full-text search.

Security findings

Secrets are environment-based, passwords are hashed, upload type/size is bounded, and raw resume bytes are withheld from responses. Yet PII, authorization data, answers and resume binaries lack a complete encryption/retention policy. Tenant isolation relies only on application filters; RLS is absent. The encrypted credential vault is process-local, unaudited and non-durable.

06 · Recommended production shape

Separate durable truth, transient work, and binary artifacts.

PostgreSQL owns tenant/user state, jobs, applications, analyses, transitions, attempts, outcomes, audit, idempotency and outbox. Redis owns queue messages, retries, leases, rate limits and cache. Private object storage owns source/generated documents and worker artifacts.

07 · Controlled evolution

No engine replacement. A staged hardening migration.

Schema mappingLive introspection, counts, duplicate/orphan reports and data classification.
Additive schemaVersioned Prisma + SQL migrations for constraints, transition history, outbox, object metadata, RLS and partitions.
Resumable backfillNormalize legacy JSON and copy binaries with ownership, checksum and encryption verification.
Dual verificationShadow reads compare counts, hashes, ownership and state before cutover.
Application migrationTransactional services, idempotent workers, BullMQ and private object storage.
Test and cut overTenant, concurrency, migration, load and restore tests; feature-flagged rollback.

Primary data-loss risks are malformed JSON, conflicting free-form states, cross-user references, binary transfer failure, nullable source identity and dual-write divergence. Destructive cleanup waits for verified checksums, row counts and a restore point.
